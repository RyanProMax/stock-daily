# Stock Daily 本机盘面研究任务

日报由本机 `scripts/run-codex-daily.sh` 调度。确定性程序先采集行情、完整一级行业和统一
AI 产业链代表篮子；本地 Codex 随后使用原生网页搜索，根据实际涨跌主动研究；本地质量门
通过后才允许发布到 Cloudflare，并从生产接口回读确认。

## V11 输入契约

`work/daily-input.json` 使用 `codex-market-research-v11`，包含：

- CN 六项、US 四项市场指标及前一交易日；
- CN、US 各十一项一级行业和四只代表成分股；
- CN、US 各八项 AI 产业链等权代表篮子；
- 两个市场的交易窗口与收盘后两小时复盘窗口；
- 由上述确定性行情生成的 `marketBriefs`。

输入不再包含候选新闻池。网页信息发现、来源追踪和归因由启用原生搜索的 Codex 完成。

## V11 输出原则

- 每个市场零至两条驱动；只允许收录有直接外部证据支持的事件或宏观原因。有驱动时恰好
  一条主驱动，第二条只能是独立且同样经过核验的次要原因。
- 缺少直接因果证据时不输出驱动，并将市场状态设为 `insufficient`；不得用行业贡献、权重、
  成分股、风格轮动或“原因未证实”占位。
- 事件或宏观解释必须同时引用本地行情和直接外部证据；专家与社交内容不能单独支撑因果。
- 每个来源必须是可直接打开的原文链接，并记录实际发布时间和来源层级。
- 行业代码只来自对应市场的一级行业列表；AI 环节代码不得混入行业字段。
- AI 视图只有在存在直接 AI 事件证据时才输出原因机制；没有直接证据时不输出动态与机制，
  并将状态设为 `insufficient`。
- 所有数字必须存在于输入行情或所引用证据的 `facts` 中，数值、单位和涨跌方向必须一致；
  日期、URL、代码和内部元数据不能充当数字证据。
- 标题、摘要、机制与英文翻译中的每个量化结论（包括中文数字词）都必须在相应 `facts`
  中用同一数值和单位明确出现；若证据摘要未记录该数字，不得把原文中的额外数字写入结论。
- CN、US 独立判断，跨市场事件只有在本地行情响应一致且存在本地证据时才能进入。
- AI 动态只纳入交易窗口内可核验的技术、订单、财报、政策或供需变化。
- 每个市场先建立至少三个候选原因，记录支持证据、反证或缺失环节和接受/拒绝/未决结论；
  只有接受的候选能够进入读者报告，并且必须与最终标题和外部证据 URL 对应。
- 驱动方向始终表示被解释行业的涨跌，不表示外部变量的方向；通胀或收益率上涨导致行业
  下跌时仍应标记为负向。接受候选必须有一条来源级因果命题完整覆盖最终发布机制。
- 每条发布给读者的驱动机制和 AI 影响分析至少一百个字符，必须完整写出已核实事实、传导
  路径和证据边界；重复涨跌、同义改写和无来源扩展不能用于满足长度要求。
- 研究 Agent 完成后由独立复盘 Agent 重新打开引用来源、执行新的市场查询，并从事实准确、
  因果逻辑、证据直接性、替代解释和读者价值五个维度验收。
- 读者页面只展示市场事实、解释和证据，不展示研究查询、工具或流水线状态。

## 完成条件

Agent 输出符合 `docs/daily-report.schema.json` 只代表生成完成。定时任务还必须依次通过：

1. 原生网页搜索审计覆盖 CN 与 US，并核对报告声明的查询确实执行过；
2. 本机实际打开报告引用的每一个外部证据 URL；
3. V11 行情、时间窗口、URL 来源层级、归因、证据、候选原因账本和数字质量门；
4. 独立复盘 Agent 的查询与来源打开审计，并且五项评分全部不低于四分；
5. Cloudflare 写入；
6. 生产接口回读与本次输入、报告逐项一致。

任何一步失败都不得把本次任务标记为完成。发布命令本身也会重复执行前两项审计，不能通过
绕开调度脚本直接写入未经审计的日报。调度器最多允许三轮“研究—验证—独立复盘”反馈重写；
第三轮仍不通过时结束并保留线上旧报告，不得降低门槛发布。
