# Stock Daily 本机多 Agent 复盘任务

`scripts/run-codex-daily.sh` 只负责采集、加锁和启动
`scripts/daily-workflow.mjs`。行情来自确定性采集程序；市场判断、网页研究、裁决、成稿、
复核和翻译由多个相互隔离的本地 Codex 进程完成。Cloudflare 只保存最终日报并提供网站。

## 执行拓扑

每个需要判断的阶段都启动新的 `codex exec --ephemeral` 进程：

1. 程序先从已收盘行情确定大盘、11 个一级行业和 8 个 AI 环节，共 20 个必查目标；横盘和小幅涨跌也纳入。Planner 另选两个核心异动和至多一个兜底，用于原有主线摘要。
2. 每个必查目标并行启动 Facts 与 Causal 两个主动检索进程，每批最多两个目标、四个进程。二者看不到对方输出；前者核实公告、
   财报、实际值和一致预期，后者核实价格反应并主动寻找竞争解释。
   两个角色分别验证输出、真实搜索事件和计划查询，成功角色立即保留；某个角色失败不会跳过后续目标。
   全目标首轮结束后，仅补试失败角色，使用该目标冻结的原始上下文。每个首轮角色在同一运行内最多两次原始调用，恢复运行不能再补出第三次；失败搜索仍计入累计额度。
   仍有角色失败就保存已完成研究、覆盖缺口和失败原件，停止归因审查、成稿及发布。
3. 确定性程序重新打开最终 URL，校验公网跳转、正文、页面发布时间、原文摘录、来源域名和
   财报数字。来源类别由 `scripts/source-registry.mjs` 计算，Agent 无权填写。
4. 独立传导审查先核对一手事实、同一事件的独立市场反应、对象完整的背景敞口、方向和反证。直接报道与明确推断分别记录；推断只能中等置信，且成稿保留所有对应引用。完整复盘 Writer 只读已验证账本，逐项解释方向、传导、涨跌幅受限或放大、竞争解释和推翻条件；每条中文归因至少 100 字。另一个独立 Reviewer 逐项核对事实、因果、幅度解释、来源独立性和读者价值，五项均须至少 4/5。任何目标不完整则保留缺口，不发布。原有主线 Adjudicator 只读取通过校验的证据账本。事实和因果证据必须来自隔离的研究进程与不同正文摘录，并共同支持同一个计划候选原因，目标与范围必须一致；
   同日事件和涨跌的机械拼接直接拒绝。
5. Writer 只读取接受的归因卡片和对应原文摘录。每条核心摘要与机制各为 100–220 个中文字，
   财报归因必须展示实际值、预期值和由程序计算的差额。
6. Reviewer 在新上下文中逐条检查事实、因果、证据直接性和读者价值，四项均须达到 4/5。
   它看不到 Writer 的提示词、对话、搜索事件或淘汰材料。
7. 失败只返工对应卡片。每轮复核都严格按 Reviewer 指定的研究、裁决或写作阶段启动新进程；
   新的 Repair Writer 不得改写已经通过的卡片，需要补证时只重跑该异动的独立研究进程。
8. Translator 只翻译通过复核的中文稿，并保持 claim ID、顺序、范围和所有数字不变。

所有阶段输入、输出和事件哈希保存在忽略版本控制的 `work/runs/` JSON 断点中，不使用本地
数据库。阶段提示词或输入哈希未变化时可复用完整产物；产物被改动或阶段失败时只重跑该阶段。
最终 V11 确定性校验失败时会主动废止成稿、复核与翻译缓存；归因卡片被移除后，后续返工输入
也会同步删除对应旧稿和旧问题，避免坏结果在恢复时循环复用。
中断或失败的运行恢复时会先写入当前采集批次的不可变输入快照，再切换运行清单中的批次标识；
发布前会核对两者一致。已经终结为无可靠归因的运行不会复用旧检索结果，下次触发会保留历史
产物并创建全新的隔离研究尝试；失败或语义校验未通过的同阶段查询仍计入已使用查询，不能伪装成
新的检索。
macOS 外层沙箱拒绝读取项目、其他阶段目录和用户主目录，仅放行当前阶段输入与 Codex 自身
运行凭据目录。进程中断时，已开始阶段的时间按该阶段硬超时上限计回持久化预算，重启不能重置预算。

## 硬性证据门

- 正式日任务每市场最多 92 条搜索：20 个目标各四条，主线与返工共享剩余 12 条。研究总预算 35 分钟，单市场整体 55 分钟；双市场外层 115 分钟硬停止。兼容旧回放的非完整路径保留 12 条/20 分钟/45 分钟预算。并行研究和
  双角色返工会在启动前一次性预留完整搜索额度。证据页面下载也接收同一个中止信号，不会绕过整体截止时间。
- 前两个异动均无可靠归因时才研究第三个。没有可靠归因时不生成卡片，也不覆盖线上该市场
  上一份有效分析。
- 每轮冻结公开 X 原帖采集。AI 官方账号、行业研究者、宏观与市场广度评论者使用身份依据白名单；账号、原帖 URL、帖子 ID 编码时间和交易窗口必须一致。观点只能署名引用，涉及事实仍须官方佐证；帖子自身或媒体转述的数字不能验证事实，无关官方引文中的相同数字也不算佐证。独立复核逐项检查主体、指标、期间、单位、方向及限定条件，区分预测和已发生结果。无合格原帖或访问失败按实际状态记录，不编造社交共识。
- 完整归因须有该目标的官方事实与另一原文的直接价格联系，或经独立审查的完整推断链。推断须以同一事件的当时反应和一手对象敞口为依据；一家公司不能扩大成整个板块或四家公司篮子的敞口。幅度解释须有目标对应的成交、盘中区间、分化、广度、相反力量或由冻结日线重建的完整幅度观测。收盘涨跌幅不冒充盘中振幅，代表股不冒充加权贡献或全市场广度。
- 首轮完整研究和传导审查后，利用原尝试剩余预算做一次按缺口定向的补证。每个入选目标保持 Facts/Causal 相互隔离，各执行两条新的查询；所有首轮目标都已研究，未解决目标按绝对变动和输入顺序分配剩余额度，横盘不被删去。最多十二条查询，不重置累计搜索、研究或整体时限。保存可重建的补证计划和上下文，恢复只复用真实指纹一致的检查点。补证取得的原文重新验证后再审查，未解决的目标不能靠重新写作变成已解释。
- 定向补证也按每批两个目标、最多四个研究进程执行。某个目标失败后继续其余已计划目标，保留成功结果、原始查询消耗及重新核验的账本和覆盖检查；失败目标阻止成稿及发布。
- 美国 AI 篮子的公司代码、发行人及年报受理时刻从 SEC 原始代码表和申报记录重建，并与年报正文的发行主体、表格及上市代码一致。原文、身份表和时间记录均冻结，缺失或矛盾保留为缺口；被提及的客户或竞争对手不能算作披露主体。跨篮子的同一成分公司沿用原始公司引用，仍须覆盖四家公司。固定利率债务等限定条件必须保留，历史风险披露不自动成为当日原因。
- 中国 AI 篮子的公司身份从巨潮原始证券名录按代码及 A 股类别唯一确定；机构身份与原站表单查询返回的每条定期披露一致。保存原始请求、响应字节、哈希和采集时间，先查询全部公司再下载报告，受共同八分钟限时及单次四十五秒限时约束。列表不完整、存在未知完整报告格式或报告期末与发布日期矛盾时不回退旧文件；摘要不进入经营证据。当前简称变化不改写历史披露中的名称，完整公司名称须与 PDF 原文相同。只有最新完整报告的正文、公司代码、机构身份、标题和日期均能从冻结原文重建时才产生该公司的背景敞口引用；仅有披露列表或下载失败仍是缺口，不能充当当日归因。
- PDF 按原始字节重建逐页文字和图片记录。封面徽标不会使整份报告失效，但引文所在页、所有可能的重复位置与中间页、前后各一页必须没有未核验的图片；扫描页、缺页、未知字体符号和非限定字体提示的解析警告仍拒绝。原始勾选符号保留，不改写成事实。发行人来自封面与其自身公司简介，首次发布日期来自对应官方记录，释义中的公司名称不能冒充封面主体。
- 中国公司背景须在同一句原文中明确连接自身经济因素与经营或财务影响。公司页眉、金融资产分类、估值及会计规则、通用声明和竞争对手描述不构成经营敞口；“毛利率”不当作市场利率，“金融资产”不当作融资条件。保留随后对冲、限制和否定敏感度的说明；入库及发布复验均执行相同规则，不能以历史披露补成当日价格原因。
- 正文下载成功和出版方身份可信，不等于其中事实正确。当天明确的收盘点位与涨跌幅须对照冻结行情，保留报道的四舍五入精度；矛盾原文拒绝用于完整复盘。明确要求订阅才能阅读的截断摘要不能冒充完整正文，拒绝只针对该 URL。
- 持续更新的新闻同时保留首次创建和当前版本时刻，核验该版本的可用时间必须有对应 URL、可见标题及原文中明确带时区的文章记录。收盘后补入的结果不能冒充凌晨已知信息；更新时刻超出交易窗口、矛盾或无法核验时，不回退旧创建时间放行。报道原始署名从对应文章重建，照片署名、被引文章和推荐内容不算来源；AP、Reuters 的不同转载或不同段落各只计一个通讯社来源。高置信需要至少两个已识别的独立报道来源。
- 针对已结束交易日的收盘报道，统一使用实际收盘后八小时的有限读取窗口；行情采集截止仍为收盘后两小时。普通事件和归因根事件必须在收盘前已知，盘后新事件不能解释当天价格；仅有日期的官方发布仍需精确计时的收盘前确认。财政部金融司原文只有在网站身份、标题、路径日期、正文署名、可见发布日期及北京时间记录全部一致时，才由程序采用该精确时刻；不得由生成结果覆盖为日期，也不得把预告实施日当作已实现结果。
- 财政部当日插值平价收益率及其前值、基点变化从冻结官方 XML 重建。它是观测而非有已知公布时刻的新闻：仅在独立报道明确同一期限、当日和前一交易日报价、且方向一致时才能支持中等置信推断。报价与平价观测须分别保留；超过 10 基点的水平差异须补充口径或时点证据，不扩大容差。未知历史公布时刻必须在中英文归因中明示。板块和 AI 篮子的完整背景敞口要求继续适用。
- 每次成功取得的原文字节、正文和时间元数据冻结保存并核对哈希；恢复运行和发布审计都重新从冻结原文验证引文、数字、单位、方向和发布时间。未取得的正文或无法重现的访问失败不能补写成已验证证据。
- BEA 原文预告的解禁时刻不等于实际发布时间。仅在官方 RSS 中找到对应 URL、标题、发布日期和唯一有效带时区记录时采用其发布时间，并冻结该条原始记录；缺失时只保留原文已证明的日期。其他发布、日历及页脚修改时间不能补成该报告的时刻。
- 搜索结果和摘要不是证据。每条引用必须能从最终页面正文中定位 Agent 提交的精确摘录，
  并从页面元数据核实发布时间。正文解码依次识别 BOM、HTTP charset 和 HTML meta charset，
  避免 GB2312/GBK 中文来源因乱码被误删。
- 财报比较必须以类型化数值记录实际值和基准值，金额还必须保留美元或人民币及其数量级；显示值必须与数值一致，原文摘录中的对应数字也必须带有相同单位和数量级。
  “超预期、低于预期、上调指引”缺少完整比较字段时整条归因不可发布。
- Facts 和 Causal 证据必须由互不可见的进程产出，且不得复用同一正文摘录；同一篇实时报道只有在两段原文分别支持事实和因果时才允许复用 URL。公司证据不得扩大为行业或指数原因；子行业、
  AI 环节和公司只能使用来源实际覆盖的最窄范围。
- 读者文案不得出现搜索过程、审核边界、淘汰理由、模型、Agent、Schema、内部评分或
  “该来源只验证”“不能据此”等过程措辞，也不得用“发生了什么”“为什么”作空洞标题。
- 英文翻译必须逐项翻译财务指标名称、预期基准名称和说明；实际值、预期值和程序计算的差额
  仍由代码从已核验类型化字段原样附加，不能改写数值或把中文标签留在英文卡片中。

## 市场隔离与发布

- CN 与 US 独立判断。`daily:close` 强制只处理 CN，`daily:run` 强制只处理 US；普通定时触发
  只选择 `marketAsOf` 真正前进的市场。未发现新收盘时不写当日成功标记，后续补偿触发仍会
  重新采集，避免行情源延迟造成漏报。
- 发布时读取线上最新日报，只替换当前市场的视图、驱动与翻译；另一市场分析和逐板块复盘原样保留。
  一个市场失败不会阻止另一个已经通过的市场发布。
- 发布内容增加精简逐目标复盘。计划、查询、证据账本、裁决、评分和断点都不会写入 D1 或 UI。
- D1 写入后必须从生产 API 回读。完整首次发布比较整份内容，包括 20 项复盘；写入成功但回读中断时，下次
  触发优先按当前市场切片哈希恢复确认。同市场同交易日有多个待恢复成稿时先处理完成时间最新的
  一份；最新一份仍待处理时会延后所有旧尝试，且任何旧 `marketAsOf` 都不能覆盖线上更新日期。
  首次写入由当前市场生成的另一市场占位切片会记录精确哈希；后续独立通过审核的另一市场即使
  属于单独批次，也只能在报告日期、市场日期和哈希全部匹配时替换该占位。该记录随断点保存，
  进程重启后仍可安全完成另一市场。
  只有回读一致才记录 `publication: published`。
- 每次运行的交付模式在创建时固定为 `shadow` 或 `publish`，并进入独立的运行标识；两种模式
  不会复用或改写彼此的断点。`--shadow` 只执行到报告与运行清单就绪，发布边界会拒绝它。
- 单个市场写入并回读成功后，整批 `ingestion_runs` 仍保持 `running`；只有本次选中的全部
  市场都完成后才统一标记为 `completed`，避免 CN 或 US 半批失败却显示整批完成。若同批另一
  市场已经终结为失败或无可靠归因，该旧批次会标记为 `failed` 并退出恢复队列，由新批次接管。
- 历史日期回放或补写由线上归档接口按请求日期做服务端截取，再选择当天或之前最近一份报告；
  不受最近 100 份列表窗口限制，也绝不把未来日报的另一市场内容倒灌到历史日期。

## 常用命令

```bash
npm run daily:run       # US，发布
npm run daily:close     # CN，发布
npm run daily:evening   # 自动选择有新收盘数据的市场，发布
npm run daily:shadow    # 自动选择市场，不写 Cloudflare
npm run daily:check -- --require-complete  # 必须通过全部板块复盘验收
scripts/run-codex-daily.sh --force --shadow --update-kind evening --market CN
npm run daily:workflow:acceptance -- --runs-root work/acceptance-runs --labels specs/verified-recap-workflow/acceptance-labels.json --require-pass
```

旧的一体化生成与复核提示词已经移除，不再存在可被调度或发布命令误用的旧入口。


## 运行期间的版本与权威时点

- 调度器在采集行情之前冻结仓库规则、工作流源码、标的配置、研究提示和依赖锁文件的哈希；采集后、每次研究调用前、证据验证、最终就绪、生产写入前及回读后重新检查。检查点恢复先封存已执行的原始调用并计入查询消耗，再检查版本。源码不一致时终止后续工作，不能把不同版本的采集、研究或审核拼成完成任务。
- 美联储讲话的日期允许原站显示零填充日数，但必须与当前讲话地址中的日期一致。精确时点来自唯一匹配标题、讲话人、link、guid、类别、有效星期和当地发布日期的官方 RSS 项；页脚和无关时间标签不可替代。
- SEC 申报可用时点必须绑定完整申报原件中的唯一申报编号、公司名称与 CIK、有效纽约接受时钟、申报日期和同名附件正文。该时点是 SEC 申报的可用时间，不能改写为发行人首次公告时间。原始附件及对应申报字节均参与发布复验。
- 已核验的 HPE 公告日期只能由其文章标题旁的唯一可见日期和同一文章的首次发布时间共同确定；当前版本更新时间仍是本次证据的可用时点，不向前回填。独立的收入指引变动和利润率预期分别绑定方向、单位及数字。
