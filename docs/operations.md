# Stock Daily 数据与运行策略

## 定时策略

- 触发时间：macOS `launchd` 每天北京时间 `09:00`、`15:00`、`21:00` 生成早间版、A 股收盘版和晚间版；Mac 到点需保持开机。
- 当前本机任务已加载，并在这些时点附近设置补偿唤醒窗口，以覆盖行情延迟及纽约夏令时切换。程序用北京时间判断版本、用真实收盘日防止重复发布；更换主机或系统时区后应重新核对本机 `launchd` 配置。
- 行情：通过 `stock-analysis-api` 无状态 `daily-pack` CLI 一次性读取 S&P 500、
  NASDAQ、DOW、美国 10 年期收益率及中美宽基；不要求 FastAPI 常驻且固定
  `persistence=none`。板块热度仍由日报使用中证全指 11 个一级行业与美国 11 个
  GICS Sector SPDR 计算，主源失败时切换备用源。
- 幅度核验：逐项冻结原始日线。A 股行业优先读取中证官方开高低收和成交记录，上证使用腾讯证券，其余标的使用 Yahoo Finance；日线必须匹配本期与前一交易日，并复核已采集的收盘值及涨跌。振幅、开盘缺口、盘中变化和前 20 日成交中位数由代码计算；当前日不进入基线。ETF 成交量不能当作整个行业资金流，AI 等权篮子不合成未经观测的盘中高低点。数据缺口保留，不能用收盘小涨小跌猜测缩量。
- 研究：每个收盘市场固定研究大盘、11 个行业和 8 个 AI 环节；每个目标并行启动互不可见的 Facts 与 Causal Agent。Planner 另选主线异动用于摘要。前者核实公告、财报和预期值，后者核实价格反应并寻找竞争解释。所有阶段均为新的临时 Codex 进程，不调用付费搜索 API。
- 来源：搜索结果只用于发现线索。确定性验证器重新打开最终原文，检查公网跳转、页面发布时间、正文精确摘录和域名注册表。Facts 与 Causal 必须来自隔离进程和不同的已验证正文片段；跨这两种职责复用同一篇收盘稿时，证据 ID、摘录和角色职责均须不同。多个明确目标引用同一支持段落时须重新核验各自目标关联，仍只算一个报道来源。未知域名和社交内容不能进入事实裁决。
- 中国公司背景：按原始巨潮名录的证券代码和机构身份查询全部 AI 篮子成分，再读取交易窗口之前最新的完整定期报告。原站只读表单限定地址和字段，不接受跳转；原始请求及响应均冻结。摘要、未支持的报告格式、未完整读取的 PDF 和主体矛盾不能成为经营敞口证据。公司改名保留历史披露名称，经济因素的完整句子与相邻限定条件一起引用；背景仍须由当日事件和对应价格反应补足，不能直接写为涨跌原因。
- 公共事件复用：由原始正文绑定的权威公共事件保留首次发现时的目标标签和同一个原文记录。其他目标只有具备独立专业报道明确连接同一事件与自身当天反应，且事件锚点、时间、范围和经济方向通过审查，才可引用这一事实根源。一般政府网页、公司公告、背景和模型预测不能使用此例外；银行子行业不能替代整个金融指数。一篇报道的不同目标摘录仍是同一报道来源，不能增加交叉佐证数量。预备覆盖率只决定是否送审，不等于归因或发布通过。
- 央行原文：已审查的沟通交流新闻格式须由原始字节同时绑定正文、正式标题、所属栏目、原文地址、发布日、正文旁的北京时间及主办机构。网页创建时间和数字网址不代表发布时间，转载、矛盾元数据及未支持格式不能借用此身份。完整政策条件随引文保留，额度和支持比例不代表实际信贷投放或价格贡献；发布前从冻结原文重新核验。旧的正面缓存须补验原文身份、时间和标题。
- PDF 证据：每条引文保存原始文件哈希、页次、相邻页和未核验图片所在页；从冻结字节独立重建并逐字段比较。引文及前后各一页含未核验图片时不入库；重复位置及中间页全部检查，不能挑选方便的文本位置。只保留已确认不影响文字解码的限定字体提示，其他警告仍失败。封面和自身简介必须与唯一官方证券记录一致，不能退回宽松身份规则绕过矛盾。中国背景引文还须通过同句主体、经济因素及业务影响检查；页眉、会计分类、表格和通用承诺不能填充覆盖率。
- 公司公告日期：已审查的 Snowflake 新闻稿格式由同一原文地址、正式标题、所属正文、发行人及三份文章摘要共同绑定原始日期。代码从正文中的交易所代码识别公司；搜索摘要、推荐文章、页脚和 CMS 别名不能提供日期或时刻。仅有发布日期就保留盘中可用时间未知，不能借伦敦地点、市场开盘时间或收盘后报道补出时刻。改版、修改声明、矛盾时间或身份必须重新审查；缓存及发布前的冻结原文审计同时重验标题、主体和日期精度。
- 文章版本：首次发布和当前原文版本的更新记录分别保存。当前版本的时刻须与同一 URL、可见标题及带时区的原始文章元数据一致；无法核验或超窗的更新不能退回旧创建时间。原始署名和通讯社归属也从该文章重建，冻结后的发布审计再次核对。不同域名上的同一通讯社转载不能增加独立来源数，未识别来源不计入高置信佐证。
- 观点核验：X 原帖的作者、时间和全文完整性与其事实可信度分别检查。署名内容中的每项数值，在中英文中都须同时对应作者原帖和所引官方段落的实际值、单位及方向；后来的官方修订不能替换作者当时的数字。明确的季度、日期翻译和比较基准由代码识别，旧数字缓存须重新核验。相同数字仍不代表相同主题，独立复核继续检查对象、指标、期间和限定条件。未读完的线程、未核实的预期和历史比较不能补成观点；采集条数上限也不能写成完整覆盖或市场共识。
- 正文读取会解码 HTML 实体及已支持的中文编码，并识别文章标题附近的发布时间。仅传输失败可在最多三个已验证的公网地址间重试，HTTP 拒绝、证书错误和大小超限不触发地址轮换。同一次运行的定向返工复用内容完全一致、已经核验的证据，事实、摘录、目标或角色改变后必须重新核验。
- 解读：Adjudicator、Writer、Reviewer 和 Translator 相互隔离。财报归因必须展示实际值、市场预期和程序计算的差额；每条核心分析为 100–220 个中文字。没有可信归因时不生成卡片，也不覆盖线上该市场上一份有效分析；该市场保持待完成，只有真实发布并通过线上回读才记录为发布成功。
- 质量门：完整路径每次单市场尝试最多 92 次搜索、35 分钟研究预算和 55 分钟整体硬停止（20 目标各四条，主线及返工共享 12 条）；并行研究先核实全部检查点的提示、结构、正文与事件哈希，再检查所需查询额度。某个进程失败后会等待已启动的同组进程结束，再记录最终失败。预算耗尽的失败尝试保留在原目录，后续触发启动独立尝试；验收统计累计所有尝试耗时。完整复盘 Reviewer 逐条给事实、因果、幅度解释、来源独立性和读者价值评分，全部不低于 4/5 且 20 项完整才可发布；失败只返工对应卡片。
- 补证：首轮全目标研究后，逐项传导审查仍未接受的目标进入一次确定性补证。全部目标已完成首轮固定研究；剩余额度按未解决目标的收盘变动绝对值、原始输入顺序分配，横盘目标继续保留。每个入选目标需要新的 Facts/Causal 独立进程各两条查询，一次最多三个目标、十二条查询，并计入原尝试累计预算。补证计划、原始审查意见和共享原文上下文按输入哈希保存，恢复时必须重建一致且检查真实提示/事件指纹；不能仅凭完成标记免计搜索。相同冻结证据中的已验证正例重新核对原文后复用，拒绝项仍单独重查。补证后重新验证原文并重新做传导审查，缺口未消除就停止，不进入成稿或发布。
- 增量门：交易日收盘版要求对应市场新收盘数据到位。CN、US 按 `marketAsOf` 独立选择；更新类型变化但行情日未推进时不重新研究，也不写当日成功标记，数据源延迟时由后续补偿窗口重新采集。
- 写入：发布只替换当前市场切片，另一市场内容原样保留；历史补写由线上接口按请求日期截取归档并选择当天或之前最近一份切片。恢复运行使用按采集批次命名的不可变输入快照，发布前必须确认快照与运行清单批次一致。Wrangler 写入 D1 后必须从生产接口回读并比较内容哈希；回读失败保留发布断点，下次触发优先恢复确认。同一市场存在多个待恢复成稿时，按完成时间从新到旧处理；最新尝试仍待处理时旧尝试全部延后，线上较新的市场日期也绝不被回退覆盖。影子回放与正式发布使用不可变且不同的运行标识，不能互相改写或复用发布状态。正常写入和恢复重试都保持 `running`；只有批次内全部市场通过线上回读后才记为 `completed`。若同批市场已经终结为失败或无可靠归因，旧批次会写为 `failed` 并退出恢复队列；暂时性发布或最终状态写入失败仍保留可恢复断点。新运行与断点恢复成功后都按生产回读确认的市场日期更新调度检查点，绝不使用未经确认的尝试日期。

同一尝试内，已完成的补充研究会连同原始输入、提示词和查询记录一起校验后恢复，即使搜索额度已用完也无需重新搜索。提示词、市场日期、计划或文件哈希改变时不会沿用。最多给两个不同异动定向补证，仍受总查询额度约束。财报附注数字和非经常性收益口径也必须对应已核验的原文。

完整任务 prompt、JSON 契约与人工试跑步骤见 [codex-daily-task.md](codex-daily-task.md)。`launchd` 只负责唤醒，Cloudflare 不承载抓取、模型调用或定时调度。

公司定期报告只能补充经营敞口，不能代替当天催化。中国公司原文须绑定官方代码表、最新完整披露记录、发行人、机构、报告标题、文件及发布日期，再从完整原始字节重建引文和页次。会计规则、承诺表格、风险名称列表、单独的经营策略或技术优化说明不能充当涨跌传导证据；相邻的条件、缓解措施、敏感性否认和管理层假设必须保留。仅保存字体符号不代表勾选状态已核验。旧版本的正面判断须重新验证；无法完整读取或没有合格经济段落时，保留原始失败和公司缺口，继续拒绝不完整报告。

运行目录同时绑定市场、交易日、冻结输入、流程版本及发布方式。升级解析或验证规则会使用独立目录，旧清单、快照和拒绝记录保持原样；同版本恢复仍使用原检查点及已消耗预算。旧证据需要明确的原始字节重验证，不能因新版本启动就改写旧快照的解析字段或借用旧完成标记。

中国收盘复盘在研究前冻结央行官方首页及其近期新闻原文。发现范围限于已核验首页身份、完整标题和指定新闻栏目；按日期及原文地址排序去重，最多读取八篇，每次请求和整项采集分别受三十秒和四分钟上限约束。路径日期只用于发现，正文实际北京时间决定是否在本期收盘前可用；首页更新时间、路径中的数字和文件创建时间不能代替发布时间。每读完一篇保存检查点，恢复时复用已冻结首页、成功原文和已记录失败。失败、未读取的超额条目和正文上下文大小限制必须保留，不能把首页发现当作全面政策搜索。

完整的短公告可以成为公共政策事实；长公告只有附件之前完整、未截断的官方公告摘要符合摘录上限时才成为种子，摘要不代表附件所有条款。完整附件供 Facts/Causal 研究条件、适用对象和实施状态，另外选取的条款仍须逐条通过原文核验。政策公布、拟支持的对象和未来贷款指令不能证明实际执行、成分公司既有敞口或板块价格因果。发布前独立重建目录与原文，检查采集账本哈希、种子事实以及证据快照中的相同原始字节；正式产物副本保留该账本。美股流程保存明确的空账本，不额外抓取中国央行新闻。

大盘、行业指数和 ETF 的传导链使用空的公司选择名单。代表股或子行业的讨论不能变成公司拆解；只有四只已确认成分的等权 AI 篮子才能按各公司分别建立链条。错误名单和原文没有的事件锚点会被拒绝，并把具体缺陷交给有次数上限的全新审查。被拒输出、提示词、原始输入和拒绝原因必须保留，不能通过自动改写输出或降低范围要求使其通过。

`npm run daily:publish -- --manifest work/runs/RUN_KEY/manifest.json` 只处理指定的正式成稿，持久化生产读回结果并按原批次检查完成状态，不重新调用研究进程，也不会顺带发布其他运行目录中的成稿。

运行前可通过 `STOCK_DAILY_CODEX_BIN` 指定兼容的 Codex CLI；默认优先使用桌面应用的 `codex-cli/bin/codex`，执行前按该版本实际支持的特性开关生成参数。本机定时任务使用项目目录中的当前脚本，更新脚本后无需重新安装定时任务。手工确认的发布结果仍须经过生产回读，才能更新 `work/last-handled-market-as-of.json`。

默认要求 `stock-analysis-api` 位于本仓库同级目录。非默认布局通过
`STOCK_ANALYSIS_API_ROOT` 指定 API 仓库绝对路径，通过 `STOCK_ANALYSIS_UV`
指定 `uv` 绝对路径。行情 CLI 失败、返回 `partial` 或六项不完整时整次采集失败，
不会回退到日报内的旧直连实现。

## 最小必要字段

`daily_reports` 只保存：

- 主键与展示元数据：日期、期号、标题、摘要、生成时间、更新类型及 CN/US 各一个行情交易日；
- 溯源元数据：Agent 模型版本；
- 精简 JSON：十项市场指标、CN/US 各十一项一级行业、各八项 AI 产业链篮子，以及中英文市场视图；
- 归因必要字段：每个市场零至两条已验证驱动、有驱动时恰好一条主驱动，以及直接证据、来源层级、发布时间、类型化财报比较和传导机制；
- 完整复盘：每个市场大盘、11 个行业、8 个 AI 环节的双语归因、幅度解释、竞争解释、推翻条件与紧凑来源；X/KOL 观点署名引用且涉及事实有官方佐证。
- AI 动态：仅保存交易窗口内有直接事件证据的环节更新；没有合格事件时只保存结构性 AI 产业链视图。

不会保存研究查询、查看来源计数、文章全文、网页 HTML、模型 prompt、模型原始响应、token 明细或调试字段。`ingestion_runs` 只记录状态、计数和截断错误，保留 90 天。

## 容量估算

以下为旧版精简日报的历史容量基线。完整 40 项双语复盘新增存储尚待首份合格实报测量，不沿用旧版每份 20 KiB 作为新预算。

按当前双语日报与周报字段上限保守估算：

- 当前 7 份扩充后日报平均约 `18.12 KiB`，规划按单份双语日报 `20 KiB`、单份双语周报 `12 KiB` 计；
- 一年日报约 `7.13 MiB`，52 份周报约 `0.61 MiB`；
- 计入 SQLite 页、索引、每日最多三条审计及 3 倍增长余量后，约 `24.82 MiB/年`；即使再增长约 50%，也约为 `38 MiB/年`。

该数字是线上数据库存储，不是运行内存；本地开发不保存 D1 副本。

## Cloudflare 免费额度判断

当前 Cloudflare 小流量形态预计为 `$0/月`：

- Pages 静态资源请求免费且不计入 Workers 请求；
- SSR 页面和读取 API 消耗 Pages Functions / Workers 请求；本机任务不消耗 Cloudflare 定时器或模型计算额度；
- D1 每天只有少量写入，保守存储约 `24–37 MiB/年`，对个人站点的免费容量仍很宽裕；

Codex Scheduled 的模型使用计入用户现有的 ChatGPT/Codex 方案，不产生 Cloudflare AI 费用；实际可用量取决于用户方案。若站点 API 流量或 D1 用量显著增长，再评估 Workers Paid。
